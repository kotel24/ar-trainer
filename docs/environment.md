# СРЕДА РАЗРАБОТКИ И СИСТЕМА КОНТРОЛЯ ВЕРСИЙ

## Среда разработки

Код тренажёра пишется на двух языках: на аналитическом этапе — на Python, на объектно-ориентированном — на Java. Значит, среда разработки должна одинаково хорошо поддерживать оба. Выбрана IntelliJ IDEA компании JetBrains: Java она поддерживает изначально, а Python подключается плагином, так что обе части проекта ведутся в одном окне. С версии 2025.3 среда распространяется единым дистрибутивом, базовые возможности которого бесплатны. В неё встроены клиент Git, отладчик и средства рефакторинга, которые особенно понадобятся на объектно-ориентированном этапе. Рассматривались также Visual Studio Code и PyCharm, однако в первой средства работы с Java заметно беднее, а вторая не поддерживает Java вовсе.

## Языки программирования

Для процедурной реализации выбран Python 3.12. На нём алгоритмы обхода и проверки сценария записываются коротко, а всё нужное для них — списки, словари, множества и очереди — уже есть в стандартной библиотеке [4; 14]. Версия 3.12 выбрана потому, что она стабильна и поддерживается плагином Python для IntelliJ IDEA.

Для объектно-ориентированной реализации выбран язык Java 21 в дистрибутиве Eclipse Temurin. Java 21 — версия с долгосрочной поддержкой, то есть обновления безопасности для неё будут выходить ещё несколько лет. В ней появились записи (records), запечатанные интерфейсы и сопоставление с образцом в операторе switch [15]. Для тренажёра это удобно: шаг сценария можно описать записью, а виды ошибок — запечатанным интерфейсом, у которого заранее известен полный список реализаций.

Чтобы убедиться, что среда настроена, в репозитории размещены две простые программы, python/hello.py и java/src/Hello.java, которые выводят версию языка.

## Система управления базами данных

Тренажёру нужно где-то хранить сценарии и результаты прохождения, и эти данные хорошо ложатся на реляционную модель. Сценарий состоит из шагов, шаги связаны зависимостями, а каждая попытка прохождения ссылается на сценарий и содержит список ошибок. Поэтому выбрана свободная реляционная СУБД PostgreSQL 18. Она поддерживает ограничения целостности и транзакции, а также тип JSONB, в котором при необходимости можно хранить описание сценария целиком [10]. Кроме того, к PostgreSQL подключаются и Python, и Java, так что обе реализации будут работать с одной и той же базой.

## Система контроля версий

Для контроля версий выбран Git 2.50.1. Это распределённая система, то есть каждая рабочая копия содержит полную историю проекта, и работать с ней можно без подключения к серверу. Git уже встроен в IntelliJ IDEA, поэтому коммиты и просмотр истории выполняются прямо из среды. Удалённый репозиторий ar-trainer размещён на GitHub, благодаря чему руководитель может открыть проект по ссылке.

В корне репозитория лежат файл README.md с темой практики и ФИО обучающегося и файл .gitignore, который исключает служебные файлы среды и результаты сборки. Разделы отчёта хранятся в каталоге docs, а код — в каталогах python, java и db. Сообщения коммитов пишутся на русском языке и объясняют, что изменилось, например «Добавлен список источников».
