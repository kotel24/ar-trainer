# Среда разработки и система контроля версий

## Среда разработки

Весь код тренажёра пишется на языке Java: на аналитическом этапе – в процедурном стиле, на объектно-ориентированном – с собственными классами. Значит, от среды разработки прежде всего требуется хорошая поддержка Java. Выбрана IntelliJ IDEA компании JetBrains, в которой Java поддерживается изначально. С версии 2025.3 среда распространяется единым дистрибутивом, базовые возможности которого бесплатны. В неё встроены клиент Git, отладчик и средства рефакторинга, которые особенно понадобятся на объектно-ориентированном этапе. Рассматривалась также Visual Studio Code, однако средства работы с Java в ней заметно беднее.

## Языки программирования

Для обеих реализаций выбран язык Java 21 в свободной реализации OpenJDK. Java 21 – версия с долгосрочной поддержкой, то есть обновления безопасности для неё будут выходить ещё несколько лет. Сначала процедурную версию планировалось написать на Python, однако от этого решения отказались. Если обе версии написаны на одном языке, то при их сравнении на объектно-ориентированном этапе все различия можно отнести к стилю программирования, а не к особенностям языков.

Процедурная версия состоит из одного класса с методом main и статическими методами, а данные в ней хранятся в стандартных коллекциях: списках ArrayList, словарях HashMap, множествах HashSet и очереди с приоритетом PriorityQueue [15]. Собственных классов для сущностей в ней нет.

Объектно-ориентированная версия, напротив, будет опираться на возможности, появившиеся в последних версиях языка. Записи (records) появились в Java 16, запечатанные интерфейсы – в Java 17, а в Java 21 окончательно введено сопоставление с образцом в операторе switch [15]. Для тренажёра все три возможности удобны: шаг сценария можно описать записью, виды ошибок – запечатанным интерфейсом, у которого заранее известен полный список реализаций, а разбор ошибок разных видов – одним оператором switch по этому интерфейсу.

Чтобы убедиться, что среда настроена, в репозитории размещена простая программа java/src/Hello.java, которая выводит версию языка.

## Система управления базами данных

Тренажёру нужно где-то хранить сценарии и результаты прохождения, и эти данные хорошо ложатся на реляционную модель. Сценарий состоит из шагов, шаги связаны зависимостями, а каждая попытка прохождения ссылается на сценарий и содержит список ошибок. Поэтому выбрана свободная реляционная СУБД PostgreSQL 18. Она поддерживает ограничения целостности и транзакции, а также тип JSONB, в котором при необходимости можно хранить описание сценария целиком [10]. Кроме того, к PostgreSQL можно подключиться из Java через стандартный интерфейс JDBC, так что обе реализации будут работать с одной и той же базой.

## Система контроля версий

Для контроля версий выбран Git 2.50.1. Это распределённая система, то есть каждая рабочая копия содержит полную историю проекта, и работать с ней можно без подключения к серверу. Git уже встроен в IntelliJ IDEA, поэтому коммиты и просмотр истории выполняются прямо из среды. Удалённый репозиторий ar-trainer размещён на GitHub, благодаря чему руководитель может открыть проект по ссылке.

В корне репозитория лежат файл README.md с темой практики и ФИО обучающегося и файл .gitignore, который исключает служебные файлы среды и результаты сборки. Разделы отчёта хранятся в каталоге docs, а код – в каталогах python, java и db. Сообщения коммитов пишутся на русском языке и объясняют, что изменилось, например «Добавлен список источников».
